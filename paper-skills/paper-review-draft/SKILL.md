# Paper Review Draft Skill

## 核心哲学：一条主线打透

> **核心叙事优先**：只锁定 1 条清晰主线，不堆砌工作量与数据，所有内容为核心故事服务
> **主线质量判定**：主线数据成体系、证据扎实，能完整讲透一个核心问题
> **支线规范安置**：薄弱证据 / 零散支线，统一放讨论、研究局限、未来工作、补充材料，不塞进主线
> **拒绝完美主义**：接受论文存在局限、未穷尽所有问题，不等到所有支线夯实再动笔
> **果断取舍支线**：砍掉无效 / 零散内容，不铺太宽导致逻辑混乱、漏洞增多
> **结构极简原则**：主线聚焦不贪多，避免内容杂糅成 "一团浆糊"

## 核心功能

本 Skill 帮助用户：
1. **主线锁定** - 从杂乱想法中提炼唯一核心叙事
2. **支线取舍** - 判断内容该进主线还是放附录/讨论
3. **结构极简** - 构建清晰有力的论文骨架
4. **审稿预判** - 从审稿人视角预判主线是否立得住

## 使用场景

| 场景 | 触发关键词 |
|------|-----------|
| 主线梳理 | "帮我理一下论文主线"、"核心故事是什么"、"聚焦一下" |
| 支线取舍 | "这段内容放哪里"、"要不要砍掉"、"这个实验还要做吗" |
| 结构诊断 | "论文结构太乱"、"感觉内容杂糅"、"逻辑不清晰" |
| 审稿预判 | "审稿人会怎么问"、"这个主线能立住吗"、"预判一下审稿意见" |

## 核心工作流：主线锁定五步法（优化版）

> **流程调整**：先做支线取舍，再锁定主线 → 通过减负看清核心

### Step 1: 支线内容盘点与初步分类
**目标**：先清理"可能的内容"，减轻认知负担

**操作步骤**：
1. 列出你目前所有想做/已做的内容（实验、分析、理论等）
2. 对每个内容，快速标记：
   - ⭐ 核心证据（直接支撑主要发现）
   - 🔶 辅助证据（间接支撑，可强化故事）
   - ❓ 探索性（结果不确定或初步）
   - 🗑️ 可疑（不清楚为什么要做）

**初步筛选原则**：
- 任何标记为 🗑️ 的 → 直接删除
- 任何标记为 ❓ 且结果不理想的 → 考虑删除
- 只保留 ⭐ 和 部分 🔶

### Step 2: 核心问题提炼（减负后）
**目标**：在清理后的内容基础上，提炼一句话主线

**诊断问题**：
- 去掉被删除的内容后，剩下的核心发现是什么？
- 如果要用一句话概括你的贡献（不含"and"），是什么？
- 读者读完 Abstract 应该记住的唯一点是什么？

**红线检查**：
- [ ] 不能包含"and"（多个贡献）
- [ ] 不能是技术细节堆砌
- [ ] 必须是可验证的 claim
- [ ] 必须与 Step 1 保留的 ⭐ 内容一致

### Step 3: 支线内容最终决策
**目标**：基于已锁定的主线，对 🔶 内容做最终判断

**分类决策树**：
```
这个 🔶 内容是否...
├─ 直接支撑核心 claim？
│   ├─ 是 → 升级为 ⭐，进主线
│   └─ 否 → 继续问
├─ 没有它主线依然完整？
│   ├─ 是 → 放 Appendix / 删除
│   └─ 否 → 升级为 ⭐，进主线
├─ 是探索性/初步结果？
│   ├─ 是 → 放 Discussion / 未来工作
│   └─ 否 → 继续问
└─ 是方法细节/实现技巧？
    ├─ 是 → 放 Appendix
    └─ 否 → 考虑删除
```

**支线安置规范**：
| 支线类型 | 安置位置 | 示例 |
|---------|---------|------|
| 薄弱证据 | Discussion → Limitation | 初步探索、样本量小 |
| 零散实验 | Appendix | 额外数据集、消融实验 |
| 实现细节 | Appendix | 超参数、伪代码 |
| 相关工作延伸 | Related Work / Future Work | 可扩展的方向 |
| 无效内容 | 删除 | 与主线无关的实验 |

### Step 4: 主线证据链梳理
**目标**：验证最终主线是否有完整证据支撑

**证据链检查清单**：
```
□ 问题存在性：是否有数据/案例证明这是个真问题？
□ 方法有效性：核心方法是否被证明有效？
□ 对比充分性：是否清楚展示比现有方法好在哪里？
□ 机制清晰性：为什么有效？机制是否讲清楚？
```

**主线质量判定标准**：
| 维度 | 合格 | 不合格 |
|------|------|--------|
| 数据体系 | 成体系、相互印证 | 零散、各自为政 |
| 证据扎实 | 可复现、统计显著 | 个案、无对照 |
| 逻辑闭环 | 问题→方法→验证→机制 | 跳跃、缺失环节 |

### Step 5: 极简结构设计
**目标**：构建清晰有力的论文骨架

**推荐结构（6段式）**：
```
1. Abstract: 问题 + 方法 + 核心结果（1个数字）
2. Introduction:
   - Para 1: 背景 → 问题
   - Para 2: 现有方法局限（聚焦gap）
   - Para 3: 本文核心洞察（一句话）
   - Para 4: 方法简介（high-level）
   - Para 5: 3个贡献点（bullet points）
   - Para 6: 论文结构
3. Method: 只讲核心方法，细节放附录
4. Experiments:
   - 主实验（支撑核心claim）
   - 关键消融（验证设计选择）
   - 机制分析（解释为什么有效）
5. Discussion: 支线内容、局限性、未来工作
6. Conclusion: 重申核心贡献
```

**结构红线**：
- [ ] 每个 section 都必须直接支撑主线
- [ ] 没有"凑数"的实验
- [ ] Related Work 不喧宾夺主
- [ ] 方法描述可复现但不过度细节

## 主线 vs 支线：对比案例

### 案例：主题稀释检测方法研究

**原始思路（主线不清）**：
```
❌ 我们在多个数据集上验证了方法A
❌ 还对比了5种不同的baseline方法
❌ 做了消融实验、可视化分析、案例研究
❌ 探索了不同超参数的影响
❌ 在3个应用场景中测试了效果
→ 读者：你到底想说什么？
```

**优化后（主线清晰）**：
```
✅ 核心发现：现有方法在主题稀释场景下失效
   ↓
✅ 核心方法：基于语义一致性的动态阈值机制
   ↓
✅ 核心验证：在主题稀释数据集上准确率提升X%
   ↓
✅ 机制解释：为什么动态阈值能解决稀释问题

支线安置：
- 其他数据集 → Appendix
- 部分baseline对比 → Appendix
- 超参数敏感性 → Appendix
- 应用场景探索 → Discussion（未来工作）
```

### 主线与支线的本质区别

| 维度 | 主线内容 | 支线内容 |
|------|---------|---------|
| **与核心 claim 关系** | 直接支撑 | 间接相关 |
| **证据强度** | 完整、扎实 | 薄弱、初步 |
| **删除后影响** | 故事断裂 | 故事依然完整 |
| **审稿质疑风险** | 必须回应 | 可承认局限 |
| **位置** | 正文核心位置 | Appendix/Discussion |

**一句话判断法则**：
> "如果审稿人质疑这个内容，我是否必须辩护？"
> - 是 → 主线
> - 否 → 支线

## Step 6: 审稿人视角预判
**目标**：验证主线是否能经得住审稿挑战

### 核心标准：如何判断 Insight 是否深刻

**深刻 Insight 的四个维度**：

| 维度 | 深刻的表现 | 肤浅的表现 | 自测问题 |
|------|-----------|-----------|---------|
| **反直觉性** | 挑战常识/现有认知 | 符合直觉、显而易见 | "读者会惊讶于这个发现吗？" |
| **解释力** | 解释一类现象的根本原因 | 只描述表面现象 | "这个 insight 能解释多少相关现象？" |
| **简洁性** | 一句话能说清核心 | 需要很多条件限定 | "去掉所有修饰，核心是什么？" |
| **可验证性** | 可通过实验验证/证伪 | 过于抽象无法验证 | "设计什么实验能证明/反驳它？" |

**Insight 深度自检清单**：
```
□ 这个 insight 是否揭示了某个被忽视的关键因素？
□ 现有方法为什么失败？我的 insight 解释了根本原因吗？
□ 如果接受这个 insight，会改变人们如何看待这个问题？
□ 这个 insight 是否足够通用（适用于一类问题，不只是我的设定）？
□ 有没有反例？反例是否在我的预期内？
```

**常见 Insight 陷阱**：
| 陷阱 | 表现 | 修正方向 |
|------|------|---------|
| "我们提出了X" | 只是新方法，没有 insight | 追问：X 解决了什么根本问题？为什么之前的方法不行？ |
| "X比Y好" | 只是性能提升，没有理解 | 追问：为什么X更好？什么条件下更好？ |
| "我们发现X很重要" | 只是消融实验发现 | 追问：为什么重要？它改变了什么认知？ |
| "综合考虑多个因素" |  insight 模糊 | 追问：哪个因素是最关键的？ |

**从 "方法" 到 "Insight" 的提炼**：
```
❌ 方法层面："我们提出了基于注意力机制的动态阈值方法"

→ 追问：为什么动态阈值有效？

✅ Insight 层面："现有方法的固定阈值假设在主题稀释场景下失效，
   因为语义一致性会随主题数量非线性下降"

→ 这个 insight 解释了：
   - 为什么现有方法失败（固定阈值假设不成立）
   - 什么条件下失败（主题稀释场景）
   - 根本原因（语义一致性的非线性变化）
```

**NeurIPS 级别的 Insight 标准**：
> "如果把这个 insight 告诉领域专家，他们会说 '原来如此' 还是 '那又怎样'？"

- **"原来如此"** = 揭示了被忽视的关键机制，改变认知 → 深刻
- **"那又怎样"** = 只是小改进，没有触及根本 → 肤浅

---

**预判检查清单**：
```
□ 核心 claim 是否过于宽泛？
□ 是否有明显的反例/边界情况？
□ 对比实验是否充分到无法质疑？
□ 机制解释是否过于牵强？
□ 是否有"这也可以"的替代方案？
```

**常见主线脆弱信号**：
| 脆弱信号 | 风险 | 加固策略 |
|---------|------|---------|
| 多个并列贡献 | 焦点分散 | 选一个最深的打透 |
| "我们做了A、B、C" | 工作量堆砌 | 提炼统一框架 |
| 实验覆盖很多数据集 | 广度≠深度 | 聚焦1-2个深入分析 |
| 消融实验过多 | 设计不自信 | 只保留关键消融 |
| 讨论部分很长 | 主线不稳 | 把讨论内容前置验证 |

## 主线诊断工具

### 主线清晰度快速检测

**一句话测试**：
```
用一句话概括你的论文（不含"and"）：
"本文提出/发现/证明了 ______，通过 ______，实现了 ______"

如果填不出来，说明主线不清晰。
```

**主线聚焦度评分**（1-5分）：
| 维度 | 1分（分散） | 5分（聚焦） |
|------|------------|------------|
| 贡献点 | 3个以上并列 | 1个核心打透 |
| 实验支撑 | 多个数据集浅尝 | 1-2个深入分析 |
| 方法复杂度 | 多模块堆砌 | 核心 insight 简洁 |
| 故事线 | 跳跃、断裂 | 环环相扣 |

**评分 < 15分**：需要主线重构
**评分 15-20分**：主线基本清晰，可微调
**评分 > 20分**：主线聚焦，检查是否过于狭窄

### 支线内容决策清单

对每个非核心内容，问自己：

```
1. 这个内容直接支撑核心 claim 吗？
   □ 是 → 进主线
   □ 否 → 继续

2. 没有这个内容，核心故事还完整吗？
   □ 是 → 考虑删除或放附录
   □ 否 → 进主线

3. 这个内容是探索性的/初步的吗？
   □ 是 → 放 Discussion
   □ 否 → 继续

4. 这个内容是实现细节吗？
   □ 是 → 放 Appendix
   □ 否 → 继续

5. 这个内容是为了"显得工作量多"吗？
   □ 是 → 果断删除
   □ 否 → 重新评估是否进主线
```

### 常见主线陷阱与对策

| 陷阱 | 症状 | 解药 |
|------|------|------|
| **"我们做了一堆实验"** | 实验多但无统一故事 | 提炼共同主题，砍掉游离实验 |
| **"方法有很多创新点"** | 多个技术模块并列 | 找最核心 insight，其他变细节 |
| **"在多个数据集上验证"** | 广度有余深度不足 | 选1-2个深入，其他放附录 |
| **"相关工作对比很全"** | Related Work 喧宾夺主 | 压缩到只讲gap，对比放实验 |
| **"消融实验很充分"** | 消融比主实验还多 | 只保留验证核心设计的消融 |

## 极简论文结构模板

### Abstract（3句话公式）
```
[问题] 现有方法在 ______ 方面存在局限。
[方法] 本文提出 ______，核心洞察是 ______。
[结果] 在 ______ 上实现了 ______（1个核心数字）。
```

### Introduction（6段式）
```
Para 1 (背景→问题):
    大背景（1句）→ 具体场景（1句）→ 核心问题（1句）

Para 2 (Gap分析):
    现有方法A的局限（1句）
    现有方法B的局限（1句）
    共同gap：______（1句）

Para 3 (核心洞察):
    本文核心发现/洞察：______（1句，这是全文灵魂）

Para 4 (方法概述):
    基于上述洞察，我们提出 ______（high-level，不讲细节）

Para 5 (贡献点):
    • 贡献1：______（对应核心洞察）
    • 贡献2：______（方法论创新）
    • 贡献3：______（实验验证）

Para 6 (结构):
    第2节相关工作，第3节方法，第4节实验，第5节结论。
```

### Method（主线聚焦版）
```
3.1 问题形式化（必须简洁）
    符号定义（最小集合）
    优化目标/任务定义

3.2 核心方法（只讲主线）
    3.2.1 核心组件A（支撑核心claim的）
    3.2.2 核心组件B（如需要）

3.3 理论分析（可选，但加分）
    关键定理 + 直观解释

[附录] 实现细节、完整伪代码、额外推导
```

### Experiments（三段式）
```
4.1 实验设置（极简）
    数据集（1-2个核心）
    Baseline（最强3-5个）
    评价指标（1-2个核心）

4.2 主实验结果（支撑核心claim）
    核心表格/图
    关键发现解读（紧扣核心洞察）

4.3 深入分析（验证机制）
    关键消融（验证设计选择）
    案例研究（直观展示效果）
    机制分析（解释为什么有效）

[附录] 额外数据集、完整消融、超参数敏感性
```

### Discussion（支线安置区）
```
5.1 研究局限（主动暴露，掌握主动权）
    • 局限1：______ → 未来工作
    • 局限2：______ → 未来工作

5.2 未来工作
    基于局限的自然延伸

5.3 结论
    重申核心贡献（一句话）
```

## 会议特定视角：NeurIPS/ICML/ICLR

### NeurIPS 审稿特点
NeurIPS 强调 **technical depth** 和 **theoretical insight**，主线需要：

| 维度 | NeurIPS 偏好 | 主线调整策略 |
|------|-------------|-------------|
| **理论深度** | 喜欢有理论保证的方法 | 如果方法有理论分析，放在主线显著位置 |
| **实验规模** | 大规模、多数据集 | 但主线仍需聚焦，额外数据集放附录 |
| **novelty** | 强调技术创新 | 核心 insight 必须在 Intro 就点明 |
| **机制理解** | 不仅有效，还要知道为什么 | 机制分析是主线必备，不是支线 |

**NeurIPS 主线检查清单**：
```
□ 核心 insight 是否足够深刻？（不只是"我们提出了X"）
□ 是否有理论分析支撑主要结论？
□ 实验是否覆盖标准 benchmark？
□ 消融实验是否验证了核心设计选择？
□ 是否清楚解释了为什么方法有效？
```

**NeurIPS 常见拒稿信号（主线问题）**：
- "The contribution is incremental" → 主线 insight 不够深刻
- "The method is heuristic" → 缺少理论支撑或机制解释
- "The experiments are limited" → 主线证据链不完整
- "The writing is unclear" → 主线表述混乱

### 与 ACL/CVPR 的差异

| 维度 | NeurIPS/ICML | ACL/CVPR |
|------|-------------|----------|
| **核心评价** | insight + 理论 | 效果 + 应用价值 |
| **实验重点** | 标准benchmark + 消融 | 多场景应用 + 案例 |
| **Related Work** | 突出技术差异 | 突出应用场景差异 |
| **失败分析** | 必须（展示理解深度） | 推荐（展示鲁棒性） |

**调整建议**：
- 投 NeurIPS：主线突出理论洞察和机制理解
- 投 ACL：主线突出语言现象和实际应用价值
- 投 CVPR：主线突出视觉效果和泛化能力

## Rebuttal 策略：主线防御战

### 核心原则
**Rebuttal 不是解释所有问题，而是捍卫核心主线。**

### 质疑分类与应对

| 质疑类型 | 优先级 | 应对策略 |
|---------|--------|---------|
| **质疑核心 claim** | P0 - 必须回应 | 补充关键实验/理论论证 |
| **质疑主线逻辑** | P0 - 必须回应 | 澄清表述 + 补充证据 |
| **支线实验不足** | P1 - 选择性回应 | 承认局限 + 放未来工作 |
| **方法细节问题** | P1 - 选择性回应 | 补充附录材料 |
| **写作建议** | P2 - 礼貌致谢 | 能改则改，不改说明 |

### 回应结构（极简版）
```markdown
**Reviewer**: "质疑内容..."

**Response**:
接受/反驳/部分接受 + 一句话立场

**Evidence**:
- 关键数据/实验结果
- 论文修改位置（如适用）

**对于无法回应的质疑**:
"这是一个有价值的方向，我们计划在后续工作中探索..."
```

### 红线：不要做的事
- [ ] 不要为了回应而增加新实验（除非直接支撑主线）
- [ ] 不要承认核心 claim 有问题（可以承认表述不清）
- [ ] 不要把支线内容强行塞进主线解释
- [ ] 不要回应所有 minor comments（选择性回应）

## 使用示例

### 示例1: 主线梳理

**User**: "我做了好多实验，但感觉论文很散，帮我理一下主线"

**Skill 引导对话**:
```
Step 1 - 一句话测试：
"用一句话概括你的核心贡献（不能带'and'）："

User: "我们提出了一个新的注意力机制，在图像分类、检测、分割上都做了实验，
      还做了消融实验、可视化分析..."

→ 诊断：这不是一句话，是实验清单。主线不清晰。

Step 2 - 核心洞察挖掘：
"去掉所有实验，你的核心方法/洞察是什么？"

User: "我们发现传统注意力的计算方式在边缘设备上效率太低，
      提出了一种基于稀疏采样的近似方法"

→ 提炼主线：
"本文提出基于稀疏采样的近似注意力机制，在保持精度的同时
 将边缘设备上的推理延迟降低X倍"

Step 3 - 支线分类：
| 内容 | 决策 | 理由 |
|------|------|------|
| 图像分类实验 | 主线保留 | 核心验证 |
| 检测+分割实验 | 放附录 | 支线验证 |
| 消融实验(5个) | 保留2个关键 | 验证设计选择 |
| 可视化分析 | 放附录 | 辅助理解 |

Step 4 - 极简结构：
Abstract: 聚焦边缘设备效率问题 + 稀疏采样方法 + 延迟降低X倍
Intro: 6段式，核心洞察是"稀疏采样可以在精度和效率间取得更好平衡"
Method: 只讲稀疏采样核心设计，其他放附录
Exp: 主实验（分类）+ 关键消融 + 机制分析
```

### 示例2: 支线取舍决策

**User**: "我在3个数据集上都做了实验，但第3个数据集效果一般，要放吗？"

**Skill 分析**:
```
决策树分析：

1. 这个数据集直接支撑核心 claim 吗？
   → 前2个是，第3个只是"额外验证"

2. 效果一般会削弱主线吗？
   → 是，读者会问"为什么在这个数据集上不行"

3. 能解释为什么效果一般吗？
   → 如果能解释清楚，可以放 Discussion 作为局限
   → 如果解释不清，果断删除

建议：
- 方案A（推荐）：删除第3个数据集，保持主线干净
- 方案B：保留但放 Appendix，正文不提
- 方案C：放 Discussion，主动解释局限

红线：不要为了"显得工作量大"而放效果不好的实验
```

### 示例3: 结构诊断

**User**: "Introduction 写了8段，感觉太长了"

**Skill 诊断**:
```
当前结构分析：
Para 1-3: 背景（深度学习发展、CNN、Transformer...）→ 过长
Para 4: 问题陈述（效率问题）
Para 5-6: 相关工作A、B、C的详细介绍 → 这是Related Work的内容
Para 7: 本文方法（很详细）
Para 8: 贡献点（5个bullet points）→ 太多

问题诊断：
❌ 背景铺陈过长
❌ Related Work 提前
❌ 方法细节过多
❌ 贡献点分散

重构建议（6段式）：
Para 1: 背景→问题（1段）
       "随着XX在XX领域的广泛应用，效率瓶颈日益凸显"

Para 2: Gap分析（1段）
       现有方法A的局限 + 现有方法B的局限 → 共同gap

Para 3: 核心洞察（1段，灵魂）
       "本文发现：通过XX方式，可以在精度和效率间取得更好平衡"

Para 4: 方法概述（1段，high-level）
       "基于此洞察，我们提出XX方法..."

Para 5: 贡献点（3个bullet）
       • 核心洞察/理论发现
       • 方法论创新
       • 实验验证

Para 6: 结构（1句）
```

## 使用流程（Agent执行指南）

当用户触发本 Skill 时，按以下流程执行：

### Step 1: 识别用户场景
```
IF 用户说"论文很散"、"主线不清"、"不知道怎么组织" → 进入【主线梳理模式】
IF 用户问"这个内容放哪里"、"要不要删掉" → 进入【支线取舍模式】
IF 用户说"Introduction太长"、"结构太乱" → 进入【结构诊断模式】
IF 用户说"审稿人会怎么看"、"预判一下" → 进入【审稿预判模式】
```

### Step 2: 主线梳理模式执行流程
```
1. 要求用户用一句话概括（不含"and"）
2. 如果做不到，追问核心洞察是什么
3. 引导用户剥离实验，找到核心方法/发现
4. 用"主线聚焦度评分"评估当前状态
5. 列出所有内容，用"支线分类决策树"逐一判断
6. 输出极简结构建议
```

### Step 3: 交互原则
- **追问而非灌输**：通过提问引导用户自己发现主线
- **强制选择**：支线取舍必须给出明确建议（删/附录/讨论）
- **红线警示**：明确告知哪些做法会破坏主线
- **模板填充**：提供可直接使用的结构模板
